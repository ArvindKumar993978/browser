Security & Protocol Architecture

1. Process Isolation & Sandbox

  • Every web tab runs inside an isolated Electron WebContentsView with sandbox: true, contextIsolation: true, nodeIntegration: false, webviewTag: false, webSecurity: true, and allowRunningInsecureContent: false.
  • Web tabs have no preload script and zero access to Node.js or browser IPC APIs.
  • Web browsing uses dedicated sessions (persist:web-default or ephemeral private-<uuid>) separate from the shell UI.

2. IPC & Privilege Boundaries

  • Only Orbit's own internal UI views receive the contextBridge API (orbitAPI).
  • Every ipcMain.handle endpoint verifies senderToManager and validates argument types before acting.
  • Browser UI views enforce a strict Content Security Policy (object-src 'none', base-uri 'none').

3. Protocol & Transport Security

  • Allowed Schemes Only: Omnibox navigation, will-navigate, will-redirect, and popup handlers allow http: and https: only—blocking file:, javascript:, data:, and vbscript:.
  • HTTPS-First Mode: External http:// navigations automatically upgrade to https:// (excluding localhost/LAN and explicit user HTTP fallbacks).
  • Strict TLS Verification: Untrusted TLS certificates are blocked and displayed with a clear warning screen; certificate errors are never silently ignored.
  • Zero-XSS Reader Mode: Article content is extracted as plain-text JSON blocks and rendered strictly via React JSX text nodes without raw HTML injection.
